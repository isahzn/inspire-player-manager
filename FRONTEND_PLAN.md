## 4. Rules (from brief + CLAUDE.md — enforced)

- Mock data matches `API_CONTRACTS.md` exactly (MSW validates against schemas). Never invent endpoints/fields — file a contract request instead.
- Money: integer minor units only, strict `parseMoneyInput`/`formatMoney` (no `parseFloat`, no `×100` on floats). Display `Rs. 4,000` / `LKR 4,000.00`.
- Invoiced vs Collected always separate; "Delivered" only when provider reported `device_delivered`/`read`. **This rule is unchanged by the OpenWA switch** — `delivery_state` is our own normalized enum (see `OPENWA_INTEGRATION` §9); OpenWA's actual ack semantics are pending spike S1 (item O19), so nothing may infer a delivered state before then.
- Mobile-first: 44px+ targets, sticky save bar with `safe-area-inset-bottom`, tables→cards < 640px. **CR-003 makes this a shipping rule, not a polish step: coach clock in/out, the automation switches, the verification queue and the dashboard cards must each be usable one-handed at 360px, and are checked on a real phone at their own step (T-UI-10..12) — not at Step 8.**
- **Proof ≠ payment is not negotiable in the UI (ADR-013/ADR-020):** no screen may render "verified", "paid" or a green tick for a checked bank transfer; it reads **Pending verification** until an owner confirms. Never let an automation-looking badge substitute for a confirmation.
- Every view: loading (skeleton ≥300ms delay) / empty / error (with requestId + Retry) / 403 / success states. Keyboard + focus + contrast + axe-clean.
- After each step: run app, check 360px + desktop, run lint + typecheck, **file a HANDOFF report in `docs/engineering/handoffs/` via `HANDOFF_TEMPLATE.md`**, update this file (done / verified / next), and correct `docs/engineering/PROJECT_STATUS.md`. Never mark done without running.
